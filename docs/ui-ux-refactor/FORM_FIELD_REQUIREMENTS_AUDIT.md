# Form field requirements audit

Evidence: backend DTOs (`backend/CareHome.Api/Dtos`), EF models (`Models/`), frontend reactive forms, controller validation.

Legend: **R** = required, **O** = optional, **A** = autogenerated on create, **RO** = read-only in UI after create, **D** = derived.

---

## Company (`company-form`)

| Field | Entity | Req | Backend | DB | Default | UI class | Current FE validation | Recommended UI |
|-------|--------|-----|---------|-----|---------|----------|----------------------|----------------|
| name | Company | R | `[Required] MaxLength(150)` | Required | — | R | required, max 150 | Label: Company name * |
| isActive | Company | O (edit) | Update DTO | default true | true | R/O | checkbox | Edit only; label: Active status |

Create: `isActive` not sent (server sets active). **Redirect after create:** list (`/companies`).

## Recommended shared patterns

1. `mat-label` with `*` only when `Validators.required` active.
2. `mat-hint` for optional and autogenerated fields.
3. Disable submit + `isSaving` on all create/update (most forms already do).
4. **Create success → list** unless detail workspace is required (resident profile is exception for funding setup — product chose list for consistency).
